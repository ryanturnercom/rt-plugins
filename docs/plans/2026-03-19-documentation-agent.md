# Documentation Agent Plan

**Date:** 2026-03-19
**Plugin:** rt-agents
**New Commands:** `documentation-config`, `documentation-create`

## Overview

Two new slash commands for the rt-agents plugin that generate internal project documentation as a single-page HTML site with PDF export capability.

- **`documentation-config`** — The "smart" agent. Scans the codebase (READMEs, OpenAPI specs, `.blueprints/`, doc folders, CLAUDE.md, etc.), extracts knowledge, and generates a structured TOML config at `.claude/rt-documentation.toml`.
- **`documentation-create`** — The "renderer" agent. Reads the config and compiles everything into a single-page HTML/CSS documentation site with PDF export.

## Design Decisions

| Question | Decision |
|----------|----------|
| Audience | Internal/non-user-facing (architecture, SOPs, API reference, runbooks) |
| Content source | Config agent scans codebase, extracts knowledge into TOML; create agent renders |
| HTML layout | Single-page scrollable with sticky sidebar nav (Stripe docs style) |
| PDF printing | All four: CSS `@media print`, Python-generated PDF (weasyprint), print button in page, and export UI with section selector |
| Output location | `.rt-documentation/` for HTML, `.rt-documentation/exports/` for timestamped PDFs |
| OpenAPI handling | Collapsible endpoints in HTML, fully expanded in print/PDF |
| Styling | Single built-in clean/professional theme (dark sidebar, light content) |
| Config re-runs | Merge mode — re-scans and merges new findings, preserving user edits |
| Sidebar nav | Two-level with search filter box |
| Blueprints | Separate appendix section at the end |
| Content mode | Per-section `mode = "verbatim"` (default) or `"summarize"` |
| Rebuild strategy | Full rebuild every run (optimize later if needed) |
| Interactive features | Minimal — sidebar nav, search, export/print selector only |
| Config format | TOML (`.claude/rt-documentation.toml`) for consistency with other rt-plugins |
| Section print control | Per-section `print = true/false` in config, plus interactive UI override at export time |

## 1. `documentation-config` Command

### Responsibility

Scan the entire project, discover documentation sources, extract content/knowledge, and produce a comprehensive TOML config file.

### Discovery Phase

The agent should scan for and detect:

1. **README files** — `**/README.md`, `**/README.*` at any depth
2. **OpenAPI / Swagger specs** — `openapi.json`, `openapi.yaml`, `swagger.json`, `swagger.yaml`, `**/openapi.*`, `**/swagger.*`
3. **Blueprint folders** — `.blueprints/epic-*/` structure
4. **Documentation folders** — `docs/`, `documentation/`, `wiki/`, `guides/`
5. **CLAUDE.md files** — Root and nested
6. **Config/env examples** — `*.example.*`, `.env.example`, `config.example.*`
7. **Architecture docs** — `ARCHITECTURE.md`, `ADR/`, `decisions/`
8. **Changelog / release notes** — `CHANGELOG.md`, `RELEASES.md`
9. **CI/CD configs** — `.github/workflows/`, `Jenkinsfile`, `.gitlab-ci.yml`
10. **Package manifests** — `package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`

### Config Generation

For each discovered source, the agent creates a section in the TOML with:

- Section title and order
- Source file path(s)
- Content mode (`verbatim` or `summarize`)
- Print inclusion flag (`true`/`false`)
- Any extracted metadata

### Merge Behavior (Re-runs)

When `.claude/rt-documentation.toml` already exists:

1. Re-scan the codebase for new/removed sources
2. Add new sections that don't exist in current config
3. Flag sections whose source files no longer exist (comment them out, don't delete)
4. Preserve all user edits (custom titles, mode overrides, ordering changes)
5. Report what changed: "Added 2 new sections, flagged 1 removed source"

### Config File Structure

```toml
# rt-documentation configuration
# Generated by: documentation-config
# Last scanned: 2026-03-19

[project]
name = "my-project"                    # Auto-detected from package manifest
description = "Project description"     # Auto-detected
output_dir = ".rt-documentation"        # Where HTML output lives
export_dir = ".rt-documentation/exports"  # Where timestamped PDFs go

# ─────────────────────────────────────────────
# Sections — ordered by [[section]] appearance
# ─────────────────────────────────────────────

[[section]]
title = "Overview"
sources = ["README.md"]
mode = "verbatim"            # verbatim | summarize
print = true                 # Include in PDF/print by default
order = 1

[[section]]
title = "Architecture"
sources = ["CLAUDE.md", "ARCHITECTURE.md"]
mode = "verbatim"
print = true
order = 2

[[section]]
title = "API Reference"
sources = ["openapi.json"]
type = "openapi"             # Triggers OpenAPI-specific rendering
mode = "verbatim"
print = true
order = 3

[[section]]
title = "Configuration Guide"
sources = ["config.example.toml", ".env.example"]
mode = "verbatim"
print = true
order = 4

[[section]]
title = "CI/CD Pipeline"
sources = [".github/workflows/deploy.yml", ".github/workflows/test.yml"]
mode = "summarize"
print = false
order = 5

[[section]]
title = "Development Guide"
sources = ["docs/development.md", "docs/setup.md"]
mode = "verbatim"
print = true
order = 6

# Appendix: Blueprints (auto-detected)
[[section]]
title = "Appendix: Project Blueprints"
sources = [".blueprints/"]
type = "blueprints"          # Triggers blueprint-specific rendering
mode = "verbatim"
print = false
order = 99
```

## 2. `documentation-create` Command

### Responsibility

Read the TOML config, gather all source content, and render a single-page HTML documentation site with PDF export.

### Pipeline

```
Config (TOML) → Read Sources → Parse/Transform → Render HTML → Write Output
                                                  ↓
                                          Generate PDF (weasyprint)
```

### Step-by-Step Flow

1. **Read config** — Parse `.claude/rt-documentation.toml`
2. **Validate sources** — Check all referenced files exist, warn on missing
3. **Read all source content** — Load each section's source files
4. **Transform content:**
   - Markdown → HTML (for `.md` files)
   - OpenAPI spec → collapsible endpoint HTML (for `type = "openapi"`)
   - Blueprint structure → appendix-style HTML (for `type = "blueprints"`)
   - Apply `mode`: verbatim passes through, summarize condenses
5. **Assemble HTML** — Single `index.html` with all sections, sidebar, search
6. **Write output** to `.rt-documentation/index.html`
7. **Generate PDF** via Python script (weasyprint) → `.rt-documentation/exports/YYYY-MM-DD_HH-MM-SS.pdf`

### HTML Structure

```
.rt-documentation/
├── index.html              # Single-page documentation (all CSS/JS inline)
└── exports/
    ├── 2026-03-19_14-30-00.pdf
    └── 2026-03-20_09-15-00.pdf
```

### HTML Page Layout


### Sidebar Features

- **Search box** at top — filters section and subsection titles as you type
- **Two-level nav** — Top-level sections, expandable subsections (e.g., API endpoints)
- **Active section highlighting** — Tracks scroll position
- **Appendix separator** — Visual divider before blueprint appendix

### OpenAPI Rendering

- Each endpoint rendered as a collapsible card
- Shows: method badge (GET/POST/etc.), path, description, parameters, request/response schemas
- **In browser:** collapsed by default, click to expand
- **In print/PDF:** all endpoints fully expanded, nothing hidden

### Blueprint Rendering (Appendix)

- Each epic gets a subsection
- Task list rendered as a table: task name, status, dependencies
- Linked task details rendered inline below the table
- Separated from main docs by a clear "Appendix" divider

### Print & PDF Export

Four mechanisms, all producing the same clean output:

1. **CSS `@media print`** — Built into the HTML
   - Hides sidebar, search, export UI
   - Expands all collapsible sections
   - Respects per-section `print` flag from config
   - Clean page breaks between major sections

2. **Python PDF generation** — `scripts/generate_pdf.py`
   - Uses `weasyprint` to render HTML → PDF
   - Auto-installs dependencies on first run (like rt-voice pattern)
   - Reads config to determine which sections to include
   - Outputs to `.rt-documentation/exports/YYYY-MM-DD_HH-MM-SS.pdf`

3. **Print button in page** — Bottom-right floating button
   - Triggers `window.print()` with the print stylesheet active

4. **Export UI with section selector** — Dropdown in footer area
   - Checkboxes for each major section (pre-checked based on config `print` flag)
   - User can override: check/uncheck sections
   - "Save PDF" button — calls the Python script with selected sections
   - "Print" button — applies selection and triggers browser print

### Styling

Single built-in professional theme:

- **Sidebar:** Dark background (#1a1a2e or similar), light text, subtle hover states
- **Content area:** White/off-white background, comfortable reading width (~800px)
- **Typography:** System font stack, clear hierarchy (h1–h4)
- **Code blocks:** Subtle background, monospace
- **API badges:** Colored method badges (GET=green, POST=blue, PUT=orange, DELETE=red)
- **Print:** Pure black on white, no backgrounds, optimized for paper

## 3. Python Scripts

### `scripts/generate_docs.py`

Main rendering script called by the `documentation-create` command.

**Responsibilities:**
- Parse TOML config
- Read and transform source files (markdown → HTML)
- Parse OpenAPI specs into structured HTML
- Assemble the full single-page HTML with inline CSS/JS
- Write to `.rt-documentation/index.html`

**Dependencies (auto-installed):**
- `markdown` — Markdown to HTML conversion
- `tomli` (or built-in `tomllib` on 3.11+) — TOML parsing
- `pyyaml` — For YAML-based OpenAPI specs
- `weasyprint` — HTML to PDF generation

### `scripts/generate_pdf.py`

Standalone PDF export script.

**Responsibilities:**
- Read the generated HTML
- Optionally filter sections based on CLI args or config
- Render to PDF via weasyprint
- Save with timestamp to exports directory

**Usage:**
```bash
# Full PDF (respects config print flags)
python scripts/generate_pdf.py

# Custom section selection (from export UI)
python scripts/generate_pdf.py --sections "Overview,Architecture,API Reference"
```

## 5. Command Flow Summary

### `/documentation-config`

```
1. Check if .claude/rt-documentation.toml exists
   ├── No  → Full scan + generate new config
   └── Yes → Merge mode: scan + merge new findings
2. Scan codebase for documentation sources
   - READMEs, OpenAPI specs, blueprints, doc folders, etc.
3. For each source: extract metadata, determine section title, set defaults
4. Generate/merge TOML config
5. Report: "Found X sources, created Y sections"
6. Open config for user review/editing
```

### `/documentation-create`

```
1. Read .claude/rt-documentation.toml
   └── If missing → Error: "Run /documentation-config first"
2. Validate all source files exist (warn on missing)
3. For each section:
   a. Read source file(s)
   b. Transform based on type (markdown, openapi, blueprints)
   c. Apply mode (verbatim reads source, summarize reads from .cache/)
4. Assemble HTML with sidebar, search, export UI
5. Write to .rt-documentation/index.html
6. Generate PDF → .rt-documentation/exports/YYYY-MM-DD_HH-MM-SS.pdf
7. Report: "Documentation generated with X sections. Open .rt-documentation/index.html"
```

## 6. Resolved Decisions

| Question | Decision |
|----------|----------|
| Summarization | Config agent summarizes at scan time, stores in `.rt-documentation/.cache/` files. TOML stays clean, create agent reads from cache. |
| Diagrams | Detect mermaid/plantuml blocks but don't render — show styled placeholder ("Diagram: see source file"). Keep page fast. |
| Git versioning | No git info in exports. Just timestamps in filenames. Keep it simple. |
| `.gitignore` | Don't touch it. User manages their own `.gitignore`. |

## 7. Future Considerations

- **Mermaid rendering** — Could embed mermaid.js later if diagram support becomes needed
- **Git commit stamping** — Could add commit hash to footer/filename if traceability becomes important
- **Multi-page output** — Could split into multiple HTML files if single-page gets too large
- **Custom themes** — Could add theme support (dark mode, corporate branding) if requested
